# Dependency ownership and build modes

## Official release build: locked npm runtime

Use Node.js 22 and npm with registry access.

```sh
npm run build
npm start
```

The default build runs `npm ci --prefix build/npm-runtime` from the committed genuine lockfile, then emits `dist-npm/`. Netlify publishes that directory; Capacitor packages the same directory. The Android workflow verifies the six npm adapter hashes inside the assembled APK. `npm run build:npm` is the assembly-only command after dependencies have been installed.

The lockfile was generated by GitHub Actions and subsequently accepted using a clean npm ci. SHA-256: `98f46d155bf0075a895a647a45d635a5f89824985584fbd2e13ea3dcb43804e2`. [Connected CI evidence](https://github.com/tvhuy99-web/SillyTavern-Card-Studio-v1.3.4/actions/runs/45801131779) at commit `5e623a3`: 15 mounted browser application checks and 29 real IndexedDB checks passed on dist-npm, in addition to ABI parity and bootstrap. The release configuration cutover itself requires a fresh CI run and Android device upgrade check.

## Offline compatibility and regression

```sh
npm run build:portable
npm run start:portable
npm run build:source
npm run start:source
npm test
```

The portable fallback emits `dist/` without registry access. The source-native snapshot build emits `dist-source/`. These are explicitly non-default release targets, retained for rollback/diagnostic parity and the existing tests. All three modes share first-party application source and storage formats. Generated portable mirrors and six source vendor snapshots remain intentional fallback/test inputs; they are not used by the default npm release's six runtime modules. Do not delete them without migrating the dependent tests and build owners.

## Dependency and release acceptance

```sh
npm run audit:npm-dependencies
npm run test:npm-runtime
APP_DIST=dist-npm npm run test:source-bootstrap
APP_DIST=dist-npm npm run test:app-browser
APP_DIST=dist-npm npm run test:storage-browser
npm run verify:vendor
```

The isolated manifest pins ten packages. Six adapter entrypoints replace snapshot modules within the source-native layout. React, ReactDOM, Zustand, Immer and JSON5 are bundled together; Map/Set initialization shares the correct Immer instance. Other adapters use public Google GenAI, Lodash, Marked and DOMPurify APIs. The dependency auditor checks pins, registry HTTPS origins, integrity entries, installed versions, optional platform dependencies, and license metadata/file digests. It is an inventory, not legal clearance or independent verification of every installed byte. Existing JSZip/EJS/Card iframe compatibility assets and CSS remain in use and require their own provenance review. The Android workflow pins Capacitor 8.0.0 at the direct-package level; a complete Android transitive dependency/Gradle lock and device matrix are not established.

All deployment outputs use staged directory publication; an interrupted publish may leave recovery directories or a lock. This is not a power-loss durability guarantee. The release pipeline runs the actual mounted Chromium and storage checks, not just the root-lookup bootstrap stub. Live provider calls and comprehensive card/device acceptance remain separate gates.
