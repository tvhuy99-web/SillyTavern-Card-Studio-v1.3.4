# Phase 1 | P08: Host RPC ownership and session-scoped generation (increment)

## Scope
Input: cumulative `STCS-Phase1-P08.zip` (266 files; original upstream commit `398165a0954f98de6c3553f32e6af2308c963260`). No UI redesign, performance tuning, data-format changes or Android Java changes. This increment continues P08; it is not a complete host migration.

## Findings and changes
- The legacy host dispatcher contained 53 case labels. Its transport handled request validation, invocation, result cloning, diagnostics and reply delivery inside a React effect. It did not track duplicate RPC IDs, or reject a success reply after a session change.
- New `src/runtime/card-runtime/host/rpc-dispatcher.js` owns the envelope, active-frame check, request validation, result validation/cloning, in-flight ID tracking and bounded recent-completion ledger (256 IDs per source by default). The existing payload-size check is injected (2 MB JSON-encoded limit); invalid/oversized arguments are rejected. A duplicate within this window is ignored, not replayed. IDs are scoped to the originating WindowProxy. Session lease captures session ID and runtime revision; stale responses are rejected (or discarded if the source is detached), and stale diagnostics are not attributed to a new session. Transport/diagnostic errors cannot leak pending IDs. This is not an authorization system; active frames can still call existing supported methods, and the lease does not bind to a document nonce or protect all handler side effects.
- New `src/runtime/card-runtime/host/chat-rpc.js` owns five message RPCs (`chat.get`, `chat.set`, `chat.create`, `chat.delete`, `chat.rotate`). The host injects current state, conversion/index/range helpers and persistence. Legacy route bodies are removed from the production output. Creation now returns the actual insertion index and inserted messages, rather than always the trailing messages, and an empty creation returns an empty messages array. The previous timestamp, role, swipe, context-state, extra, range and 500-item constraints are retained. Persist only after checking the session lease. The host save adapter captures persona/character names before awaiting persistence, rather than reading a different session on completion. The underlying session save/storage implementation is not replaced.
- New `src/runtime/card-runtime/host/generation-tasks.js` owns frame-scoped generation IDs, AbortController registration, task cleanup and generation orchestration. A duplicate generation ID within a frame is rejected; another frame may use the same ID. `generation.stop` and `generation.stopAll` act on the calling frame, instead of globally stopping every card. Card generation is registered with the existing Runtime State, so a global Stop/session invalidation also aborts these controllers. The legacy prompt builder now checks the generation/session lease before applying returned chat/global variable updates. The extracted service checks ownership before provider calls, on chunks and completion, preserves event names, custom API routing, request shape and response text. Card generation can stop waiting when a prompt/provider/iterator ignores the abort signal; actual remote cancellation still depends on the provider. Detached frames are checked when execution resumes; no immediate removal observer or host-side timeout was added.
- New `src/core/async/cancellation.js` owns the existing `abortError`/`awaitAbortable` helper extracted from Conversation Service and an abort-aware iterator wrapper. Both chat and card generation reuse the same cancellation primitive; the previous chat streaming timeouts remain unchanged.
- Generated assets are mapped through the existing Asset Manifest under `assets/m4` to preserve relative ESM layout. The old M7 asset-root allowlist is replaced by the canonical recursive `verifyAssetInventory()` check. `applyHostRpcBoundary` is a temporary integration function in the existing card-runtime transform, called after other transforms. It binds dependencies and routes to source modules; no new transform file is created, but the legacy integration count/complexity is not eliminated. The original legacy input remains unchanged.
