# Phase 1 – P08 Catalog Ownership

Baseline: STCS-Phase1-P08-State.zip; cumulative from commit 398165a0954f98de6c3553f32e6af2308c963260. Partial P08 migration, no GitHub writes.

## Scope and architecture

- Add `src/features/catalog/catalog-mutations.js` with separate Character, Persona and Preset store action factories. UI actions and Host RPC share these mutations; UI wrappers retain error reporting, strict RPC actions propagate persistence failures. Each factory serializes its migrated mutations; selection is not used as an implicit write target. Character/Preset replacement merges the latest record within the queue. A queued RPC checks its session/frame lease before writing; Character also checks after avatar preparation. An already committed database operation is not undone on lease invalidation.
- Add `src/runtime/card-runtime/host/catalog-rpc.js`; migrate 11 existing RPCs (`character.create`, `character.replace`, `character.delete`, `character.select`, `persona.create`, `persona.replace`, `persona.delete`, `preset.create`, `preset.replace`, `preset.delete`, `preset.rename`). Explicit select and successful creation retain existing selection semantics. Character replace/delete and Preset replace/delete never temporarily select a target. If the record being deleted is still selected after commit, choose the existing fallback; preserve unrelated current selection. Character replacement matches the current session by fileName when available, not a shared display name; recheck lease before publishing the session update. Persona and Preset replacement use current session state after persistence. Delete of a missing target now returns false, and strict errors are not reported as success.
- Extend existing Entity Repositories with `add` (IDB add, no overwrite) and atomic `renamePreset`: read stored old record, normalize under new name, add and delete old key in one transaction. Destination collision aborts. Preset creation combines defaults and RPC overrides before one add. Keep database name, version, key paths and normalization contract.
- Update existing Host boundary and Asset Manifest, no new transform file. Remove superseded inline mutation implementations, replacing with dependency binding. A legacy Character creation/import handler, avatar handling, preset duplicate/revert/import and the rest of the application stores still exist.

## Remaining risks and migration work

- No real browser E2E/IndexedDB, APK, external card or API tests in this iteration. The transaction test is a simulation, not proof on real IndexedDB. No complete verification of Zustand/Immer integration through browser interactions.
- The queues cover migrated actions in each store, not all mutation paths, all tabs, imports, avatar changes, autosave or backup/restore. Concurrent Persona replacement still constructs its merged record before queue entry. Character creation delegates to the original store action; in-flight committed writes cannot be rolled back by lease checks. Deleting the currently open character may still race with autosave; renaming a preset does not migrate historical session preset references. Existing session persistence callback behavior is retained.
- Lorebook, extension lifecycle, raw import, chat refresh/save/rename, preset load/get, slash commands and remaining RPCs still need ownership review. Runtime permission/authentication, cross-frame conflict handling and .jsfrag conversion are incomplete. P09-P12 not started; do not remove legacy input or transforms. No performance optimization or UI redesign.
