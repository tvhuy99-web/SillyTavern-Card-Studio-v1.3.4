## U01–U04 follow-up: write ownership closure
Baseline: `69bec7d`. Ordinary connection, proxy, feature settings, persona selection, model catalog, speech settings and Card Runtime storage writes now use guarded production ports. Backup and recovery have distinct raw storage ports. Normal imports and editor claims participate in the entity write boundary. The session queue returns a committed/discarded result, and the coordinator does not report discarded writes as saved. In-flight local transactions are drained before restore; asynchronous ordinary database writes use shared Web Locks where supported and restore uses an exclusive lock.

Regression tests in `tests/phase1-t02-write-guard-integration.mjs` cover the previous guard bypass, unresolved recovery, discarded save, in-flight write before snapshot, and shared/exclusive Web Locks protocol simulation. `test:native-java` passed locally on JDK 21 (19 Java source files and 4 WebView expressions); it does not establish Android SDK compilation.

Remaining limits: synchronous Web Storage uses a checked advisory lease, not an atomic cross-tab transaction. The fallback without Web Locks does not guarantee cross-tab exclusion, and real browser / multi-tab behavior has not been established. Chromium application and storage acceptance timed out without a result. Registry DNS failed with `EAI_AGAIN`; no genuine lockfile or npm build was generated. No Android SDK/device or live API acceptance was performed.
