# Phase 1 – P08 Lorebook and remaining state RPC ownership

Baseline: STCS-Phase1-P08-Catalog.zip, cumulative from original commit 398165a0954f98de6c3553f32e6af2308c963260. No GitHub write. No UI redesign or performance benchmark.

## Changes

- `src/features/world-info/lorebook-mutations.js`: strict save/update/delete actions and a shared serialized queue for the migrated UI and RPC operations. A queued update reads the latest record in the queue, checks its lease before database writes, and updates the catalog after persistence succeeds. UI wrappers still report errors in their store. Imported books continue to be merged by name as before; delete of a missing catalog name retains the previous idempotent return value. Direct legacy file import/reload and backup/restore do not participate in this queue.
- `src/runtime/card-runtime/host/lorebook-rpc.js`: eight methods (names, entries.get/replace/create/delete, create, delete, raw.import.worldbook). Resolves embedded character books separately from catalog books, preserving embedded precedence when names collide. Catalog entry mutations operate on the latest committed list; automatic UID allocation avoids collisions with other automatic entries and explicit numeric IDs in the same batch. Existing explicit IDs are preserved (no universal uniqueness constraint). Embedded RPC writes are serialized separately; save session extension metadata through existing callback, recheck lease and suppress an obsolete embedded state notification after another owner replaces its book. A stale request after asynchronous worldbook parsing is rejected before saving. Import decoding/validation still delegates to the existing parser.
- `state-rpc.js`: four extension lifecycle methods and raw.import.regex. Extension lifecycle preserves existing metadata-only semantics (does not download or install executable code). Regex import uses the canonical regex.replace handler after parsing and rechecks character identity and lease. Uses a null-prototype intermediate extension record for arbitrary IDs.
- `chat-rpc.js`: four session methods (refresh, reload, save, rename), reuses existing session and extension persistence dependencies; preserves refresh/reload distinction. No new storage schema, no new transform file. Remove old host Lorebook resolver and replace old handler bodies through existing Card Runtime integration boundary. The remaining 8 methods in legacy switch are raw.import.character, raw.import.preset, raw.import.chat, slash.execute, generation.models, preset.get, preset.load, scripts.buttons. 45/53 handlers now route to source modules or previously migrated generation lifecycle; some still rely on legacy callbacks.

## Limitations

- Tests use mocks, not browser IndexedDB or Android or real external cards/API. No browser E2E confirmation of Immer integration or actual UI events. Existing saveSession callbacks may swallow persistence errors; a host in-memory mutation is not rolled back if a later save fails. A lease cannot undo an already committed write. The queues are not a cross-tab transaction protocol; direct UI import/reload, backup/restore and other store updates can still race. A full replacement deliberately replaces the whole entry list. Legacy records with duplicated explicit UIDs are not cleaned or renumbered by this change.
- Runtime permissions, iframe state synchronization, fragment conversion, P09 UI recovery and P11 legacy removal remain incomplete. Do not remove the legacy input or transforms yet.
