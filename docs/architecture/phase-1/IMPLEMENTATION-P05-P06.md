## Implemented
- `src/app/state/runtime-state.js`: a monotonic, in-memory session revision, separate from the stored session ID. Route change, session identity change and reset invalidate pending work and abort tracked controllers. Stop aborts requests without changing session identity. No revision persisted.
- `src/app/persistence/session-save-coordinator.js`: route-bound, revision-aware deferred snapshot and timer ownership; reuses existing 500 ms debounce and 750 ms busy retry. Scheduled writes are discarded when identity/revision no longer matches, including a reopened session with the same ID. Explicit save and cleanup use the same coordinator. Snapshot ID is checked before enqueue; failed writes can be retried from a fresh snapshot while the same lifecycle remains active. A shared serialized write queue survives hook remounts and failures; session loading waits for its queued writes to settle. Existing IndexedDB contract and schema remain unchanged. The queue covers these hook saves, not every independent import/delete/backup operation or other browser tabs. On a switch, the old cleanup flushes only if it still owns the session; it does not promise to persist data no longer present in memory or an in-flight partial stream.
- `src/features/chat/conversation-service.js`: capture ownership before asynchronous work; check after initial paint, before-turn preparation, Smart Scan and prompt construction, and before committing generation results. A stopped non-streaming request now receives `AbortSignal`, settles locally even if its provider ignores cancellation, clears the transient placeholder when still the same session, and ignores a late result. Streaming waits race with cancellation and retain committed partial content for same-session Stop. Both Arena sides are linked to the parent controller; stale turns cannot update the new store or clear its loading state. Logs produced within old callbacks/provider internals may still appear; cancellation does not guarantee the provider stopped processing server-side.
- `src/features/chat/response-processor.js`: validate revision, session ID and message presence after asynchronous output processing before follow-on RPG/log/sound writes. This does not cancel work or writes *inside* legacy `processOutput` or standalone Mythic.
- Arena retry moved out of the minified UI handler into `conversationService.retryArena`. Reuses shared stream/watchdog, live stream snapshots, completion/status handling, cancellation and prompt variable application. Preserves original model/provider/profile and active lorebook UIDs; creates controller before paint, excludes retried message from the prompt, handles replaceText snapshots, and leaves the other side intact. Corrected AI Studio main model selection and fallback retry selection, which formerly used the OpenRouter model field. No simultaneous native AI Studio concurrency guarantee. Existing Arena selection/manual Mythic handlers remain legacy.
- Existing M4/M5 transforms now delegate to source-owned services. Removed redundant retry prompt transform and replaced seven retry-specific transforms with one handler binding (declared M4 patch count 34→33, M5 49→43). No new transform file. Generated assets remain transitionally tracked under the manifest.
