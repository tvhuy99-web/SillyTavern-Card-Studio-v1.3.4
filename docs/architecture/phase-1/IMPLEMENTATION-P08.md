# Phase 1 | P08: Card Runtime API ownership and RPC lifecycle (increment)

## Scope
Input: cumulative `STCS-Phase1-P07.zip`, original upstream commit `398165a0954f98de6c3553f32e6af2308c963260`. No UI redesign or performance tuning. P08 is a partial migration: preserve existing runtime surfaces and classic-script/opaque-origin support while reducing duplicated implementations and extracting an independently testable bridge client.

## Changes
- Removed 21 overwritten direct API definitions (Character 5, Persona 6, Preset 4, Extension 5, EJS 1) and 26 overwritten unsupported-operation stubs (9 extension/raw import, 5 character, 5 persona, 7 preset). The canonical catalog/character/persona/preset/extension fragments are installed before the TavernHelper facade captures functions. Preserve `RawCharacter`, `getCharData`, history helpers and preset classifiers. Removed the second manual republishing list in `context-exposure`; moved the five audio command adapters to their audio module so the facade receives the correct functions at its initial construction. No removal of public API names intended. Remaining compatibility overwrites and initialization dependencies are not fully eliminated.
- New self-contained ESM `src/runtime/card-runtime/bridge/rpc-client.js` owns request IDs, pending requests, timeouts, settlement and cleanup. Build embeds the exact tested factory via `Function.prototype.toString` into the classic script; no separate network load in safe mode. The `.jsfrag` now adapts the window transport and diagnostics. Request and response envelope, timeout defaults, parent-source check and public `cardRuntimeRpc` are preserved. A synchronous send/clone failure clears pending state and timer immediately; late/duplicate replies do not settle a request twice. On non-persisted `pagehide`, reject pending calls and close the client; on persisted `pagehide`, cancel pending requests without permanently closing it. These are iframe-local lifecycle operations; they do NOT abort work already sent to the host. The browser may not dispatch pagehide on every iframe removal.
- Move handshake start/timeout/failure into `bridge-handshake.jsfrag`. Duplicate or late ACKs no longer reapply old state or replay APP_READY. Ignore replies from other windows; clear timers on failure; handle synchronous HANDSHAKE_INIT send failure and non-persisted pagehide before ready. State updates continue via CARD_RUNTIME_STATE_UPDATE. The existing 5-second handshake deadline remains. No host RPC dispatcher change, no protocol version change.
- Build has explicit catalog-before-facade and remaining compatibility composition phases. Remove no-op `toClassicRuntimeSource`. 17 core fragments and six compatibility fragments remain; full modularization of their shared lexical scope is deferred. No new legacy application transform.

## Verification
- Node 22.16.0 / npm 10.9.2. `npm run build` PASS; `npm test` **45/45 files PASS** (44 existing + `phase1-card-runtime-ownership.mjs`). New tests use a deterministic timer and mock transport to check success, errors, timeout, duplicate responses, synchronous send failure, cancel and close. They execute the actual generated classic runtime in Node VM with a minimal host/DOM fixture for four combinations: safe/full and current/official-local. Assertions check catalog results, public aliases, EJS/MVU surface, trusted parent ACK, one APP_READY, variable state update, duplicate ACK suppression, RPC sender validation, pagehide and handshake timeout/send failure/close-before-ready. Existing architecture string assertions moved to the new handshake owner. These tests are not real browser, dependency CDN or third-party card compatibility tests.
- TypeScript 5.8.3 literal module graph: src 42 JS files, assets 46 JS files; zero parse errors, missing literal relative targets or detected import cycles. Does not cover implicit fragment dependencies or RPC graph. Generated classic runtime parsed and executed by VM tests.
- `core.template.js` 370 -> 328 lines; generated core builder 195,478 -> 193,666 bytes. No claim of performance improvement. Main production bundle, renderer, CSS, Android Java, original legacy input and other deployed assets unchanged; only generated Card Runtime core builder differs.
