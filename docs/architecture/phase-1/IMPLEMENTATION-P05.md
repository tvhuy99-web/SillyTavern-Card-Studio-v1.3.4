## Scope
Input: STCS-Phase1-P03-P04-Completion.zip; upstream baseline 398165a0954f98de6c3553f32e6af2308c963260. This increment addresses application IndexedDB ownership, multi-record transactions and session record contracts. No CSS, Android Java, Card Runtime, legacy input or provider changes. P05 is not yet fully closed.

## Implemented
- `src/app/persistence/app-database.js`: one owner for application IndexedDB connection lifecycle, schema constants, read/write transaction handling and errors. Retains `SillyTavernCardStudioDB`, version 6 and all five current stores/key paths. Missing stores are created on upgrade. Historical `character_session` and `preset_session` stores are no longer deleted automatically on upgrade; no new schema version or implicit historical data migration is introduced. Rejects on abort, resolves on transaction completion, invalidates cached connection on open failure or version change. Embedding DB and Card Runtime storage remain separate domains.
- `src/app/persistence/entity-repositories.js`: named session, character, preset, persona and lorebook repositories. Source-owned preset normalization on list/get/put and batch merge. Character avatar serialization preserves byte buffer, filename and MIME; object URLs remain runtime-only. The existing legacy build transform only wires old identifiers to the new source modules; the previous inline application DB and CRUD implementations no longer ship in production. Generated assets are emitted through the existing asset manifest.
- Full system restore prepares avatar buffers before writing; all five IndexedDB stores are merged in one read/write transaction. Existing overwrite/merge behavior retained, unrelated records untouched. Adventure import likewise commits related entities and session together; diagnostics dropped only after successful commit. Local/session storage settings restore still happens separately after the database commit, not part of the transaction. Do not claim cross-storage atomicity.
- Character deletion and linked session deletion occur in one transaction with cursor scan. Story Mode overwrite no longer deletes existing record before replacing it and no longer swallows the lookup failure. Transactional consistency does not by itself resolve pending autosaves or multi-tab conflicts.
- `session-state.js`: declares persisted identity/metadata and content fields, derives excluded keys from runtime/diagnostic contracts, honors explicit null Arena overrides, removes obsolete `arenaUserProfileId` alias after preserving canonical precedence. Retains existing history compaction and snapshot behavior; unknown fields survive the load normalizer and backup merge, but snapshot allowlist remains deliberate. No bulk rewrite of existing records.
