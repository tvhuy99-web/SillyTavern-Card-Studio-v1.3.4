# P09: Connection Settings source recovery

Baseline: `STCS-Phase1-P09-Shell.zip`. Scope: Phase 1 architecture, with limited correctness fixes; no redesign.

## Source ownership

| Source | Responsibility |
|---|---|
| `src/ui/settings/connection-settings-screen.js` | Screen layout, source selection, conditional provider rendering, advanced settings, Apply action |
| `src/ui/settings/settings-controller.js` | Draft state, initial reads, profile selection/creation, model list state, Apply, shared Proxy model refresh |
| `src/ui/settings/provider-sections.js` | Four provider-specific render helpers, preserving existing DOM/JSX shape and controls |

The previous `Nd` component is replaced by one named factory with lazily resolved host dependencies. It uses the same React instance and JSX runtime. The four render helpers are not independently mounted React components; they do not introduce hooks or extra nodes. The former unused source-selector button helper was removed. The screen's Apply callback is now owned by the controller, not embedded in the JSX. Existing credentials, storage keys, manual Model IDs, AI Studio immediate-save fields, Proxy profile metadata, and advanced settings behavior are retained. The first 29 recognized hook usages in the previous component were moved into the controller, with one additional ref for Proxy request ownership. No new transform file; existing build wiring extracts the screen after preceding transforms and verifies the SHA-256 of the exact old arrow function before replacing it.

## Correctness fixes

- Manual Proxy model refresh previously shadowed its outer settings variable (`let t=await Ws(y,x,w,t.proxy_protocol)`), causing a temporal dead zone ReferenceError before the API call. Manual refresh and profile auto-refresh now call the same controller action with a captured target including URL, password, legacy mode and protocol.
- A monotonically increasing request revision prevents an earlier refresh from publishing models/cache updates or clearing the loading flag of a newer request. Invalidation covers profile selection, source/protocol changes, editing URL/password/legacy mode, and clearing the saved model list. This does not cancel the remote request and does not redesign the URL-only persistent cache.

## Remaining work and limitations

- This is incremental source recovery, not a recovered original React project. The previous transforms still run against legacy input before the fingerprinted replacement; retiring those patches requires redesigning the build pipeline. 113 heuristic UI candidates remain in the generated host. Some provider section callbacks still manage I/O and profile mutations; these require further extraction.
- The existing DOM-based Model Test enhancer and AI Studio model-button diagnostic interceptor remain installed to preserve behavior. In particular, the interceptor can still take over the AI Studio button rather than invoke the recovered callback. Direct callback tests do not prove the actual browser click path or native bridge. Next work: move explicit model-test controls and AI Studio diagnostics into React, retain fallback enhancer for unrecovered screens until all call sites migrate.
- Apply spans local/session storage and catalog writes and remains non-atomic. Proxy Ping retains its previous semantics (not an authenticated or protocol-aware test). Existing URL-only Proxy cache is unchanged; profile import/export and overlapping operations outside this controller are not fully protected.
- No mounted React/browser E2E, real provider requests, Android APK, or visual regression test in this delivery. Tests use mocked JSX/hooks/transport. No push to GitHub.
